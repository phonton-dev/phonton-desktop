# Phonton Desktop 0.4.0-beta.1

Local beta candidate; public engine source is pinned, with installed-app and
signed distribution evidence still required before release.

- [fixed] Make enabled Settings button labels readable in every theme, including
  hover states, with dedicated foreground colors for filled accent controls.

- [fixed] Replace the Unix engine launch shell so normal Desktop close stops the
  owned CLI instead of leaving it listening. Separately started runtimes remain
  independent; fresh installed Linux/AppImage acceptance is required.

- [fixed] Complete the Settings update flow with explicit installation and
  progress. A withdrawn update no longer leaves setup's controls stuck busy.
  Installation is shared across views and blocked while engine work, a pending
  change or an unconfirmed mutation could be interrupted.

- [changed] Make runtime recovery actionable, with Start runtime for a stopped
  installed runtime and the exact diagnostic available under Technical details.
  Existing storage, process-identity and execution gates remain in force.

- [fixed] Hold public tag releases from this source while trusted publisher
  signing, signed-byte provenance and installed platform/update acceptance are
  incomplete. Manual cloud candidates remain available.

- [fixed] Correct MSI's local-engine filenames to match the runtime loader.
- [added] Independent MSI and NSIS full installed journeys, exact payload checks,
  and MSI registration/log evidence. A completed cloud run is required to accept
  each installer; packaging checks alone do not certify installed behavior.

- [changed] Unify the workbench, models, settings and account setup around
  readable type, restrained Graphite surfaces and persistent navigation.
- [fixed] Keep drafts across Settings and optional online setup, with explicit
  engine-directory checks before hosted goals or workspace configuration writes.
- [fixed] Cancel automatic update prompts when returning to local work, including
  late update-check responses. Welcome-screen checks are explicitly requested.

- [changed] A calmer workbench with readable interface text, a compact header,
  an immediately visible goal composer and expandable history and machine details.
- [changed] Model selection foregrounds installed models, calibration and fit.
- [fixed] Partial checks, API cost and runtime origin use evidence-specific labels.
- [fixed] Windows release packaging resolves Tauri's release build profile correctly.
- [fixed] Windows MSI packaging uses numeric version `0.4.0.1`; the app and
  release asset names retain `0.4.0-beta.1`. Preflight catches stale MSI versions
  before compiling, while MSI installation and upgrade checks remain separate.
- [fixed] Release metadata rejects mismatched versions and keeps beta builds out
  of stable update discovery.

- [added] Standard release-candidate builds without publication and an installed
  Windows NSIS acceptance dependency before publishing the exact tested installer.

Windows x64 Preview packages contain a hash-checked 0.22.0 local engine. macOS and
Linux native packages and signed update delivery need their own release evidence.
