# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

React UI inside the existing Tauri desktop application. Desktop is the main
entry point; CLI uses the same execution and model-management core.

## Users and purpose

Developers doing real repository work with local coding models. The requested
success path is hardware detection, model installation, measured calibration,
goal execution, verification and a reviewable change with evidence.

## Constraints

Local use requires no online account. Network model downloads are explicit;
local inference must not silently fall back to cloud services. Unknown hardware,
unavailable checks and failed probes remain visible. No simulated data, progress,
benchmarks, or successful receipts. Preserve useful existing integrations.

## Brand commitments

The supplied 2026-09-22 brief and screenshot specify a sparse, near-black,
monospace, ASCII-inspired graphical application. Keep the central composer;
show repository, local mode, permissions and selected model around it. During
execution, evolve that surface into compact plan, candidate, diff and evidence
views. Avoid turning it into a generic IDE dashboard or fake terminal.

## Evidence boundary

The source implements an existing desktop shell and shared CLI sidecar. The
revival is in progress. Build, browser, native, inference and verified repository
work are separate acceptance checks; no completion is implied by this document.
